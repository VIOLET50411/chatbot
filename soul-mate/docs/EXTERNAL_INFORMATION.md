# RSS、X、小红书与网络图片

这四项不是一个开关：

| 能力 | 当前实现 | 需要你做什么 |
| --- | --- | --- |
| RSS | 已实现，可直接使用真实订阅地址 | 给每个人物填写想看的 feed |
| X 官方 API | 已实现文字读取 | 申请 Bearer Token，并填写公开账号 |
| X / 小红书真人浏览器 | Soul Mate 的只读代理和接口已实现；上游常驻浏览器需另行部署并人工登录 | 准备专用小号、登录和维护浏览器 |
| 网络图片手工导入 | 已实现下载、来源、联系人绑定、审核和私聊世界线模式 | 粘贴原帖地址、图片直链和内容说明 |
| 从已审核图片库按对话场景自主挑选发送 | 已实现；决策器只看当前联系人可用摘要，找不到合适图片就不发 | 先手工导入、写清图片内容并审核通过 |
| 自动从社交平台抓取图片候选 | 尚未实现 | 需要先部署带登录态的上游浏览器服务 |

## RSS：最简单、最稳

位置：`日志与设置 → 当前人物的模型与外界信息 → 新闻、X 与小红书`。

每行格式：

```text
来源名称 | https://真实的订阅地址.xml
```

灰色的 `example.com` 只是格式示例，不是可用配置。杜佳颖和纪雨的 RSS 列表分别保存；先切换人物，再填写和保存。随后点“测试外界信息读取”或页面下方“立即刷新”。

RSS 不需要 API Key。推荐先只配 3–8 个真正关心的来源，避免主动分享被大量低价值资讯淹没。

## X 官方 API

需要两项：

1. `X 公开账号`：逗号分隔，不写 `@` 也可以；
2. `X Bearer Token`：由 X Developer 平台提供。

两项都填才算已配置。该路径读取指定公开账号文字，不读取你的私人首页。X 官方端点需要对应 API 套餐权限；没有套餐时可以留空，不影响微信和 PWA。官方端点示例见 [GET /2/users/{id}/tweets](https://developer.x.com/apitools/api?endpoint=%2F2%2Fusers%2F%7Bid%7D%2Ftweets&method=get)。

## 真人浏览器为什么还不能直接勾选

管理台中的“宿主代理地址 `http://host.docker.internal:8280`”只代表：Docker 会到 Windows 的 8280 端口寻找一个带鉴权的只读代理。

完整链路是：

```text
Docker 核心
  → Windows 8280 Soul Mate 只读代理
  → 本机/SSH 隧道 8272、8273
  → ai-social-browser 动作服务
  → 人工登录并长期保留登录态的 Chrome
```

当前仓库已经完成 8280 代理，并且只允许 `feed / search / profile / read`；点赞、回复、关注、转发和发布不会转发。现在缺的是后半段常驻 Chrome 和 8272/8273 动作服务，因此只勾选“允许只读 X/小红书”不会凭空生效。

`ai-social-browser` 官方项目明确要求带界面的真实 Chrome、人工登录和独立小号；动作服务本身没有鉴权，原始端口只能绑定回环地址。它也明确提醒平台风控和封号风险。[项目说明](https://github.com/blueberriely/ai-social-browser)

### 推荐接入顺序

1. 先让纪雨微信文字、图片和语音稳定运行。
2. 准备只用于机器人浏览的 X / 小红书小号，不用主号。
3. 选择运行位置：以后有 VPS 时按原项目的 Linux 方案最省事；当前 Windows 可通过 WSL2/Linux 虚拟机先测试。
4. 人工登录并手动使用几天，验证码始终由你处理。
5. 启动原项目的 `twitter-tool` 8272 和 `xiaohongshu-tool` 8273，二者只监听 `127.0.0.1`。
6. 如果动作服务在 VPS，通过 SSH 本地转发把 VPS 的 8272/8273 映射到 Windows 回环地址，不把原始端口暴露公网。
7. 在 Soul Mate 管理台生成至少 24 位代理 Token，并保存。
8. 使用同一 Token 启动：

   ```powershell
   .\scripts\start_social_browser_proxy.ps1 -Install
   ```

9. 管理台保留代理地址 `http://host.docker.internal:8280`，再勾选对应平台并测试。

代理 Token 目前属于 Windows 宿主启动凭据。管理台保存后，启动宿主代理前还需要把同一个值写入 `.env` 的 `SOCIAL_BROWSER_PROXY_TOKEN`，这是少数不能只靠 Docker 数据库完成的配置；后续会把宿主代理改成从核心领取短期凭据，消除这一步重复配置。

## 私聊世界线图片

位置：`微信与媒体 → 保存网上找到的图片`。

选择“私聊世界线图片”后：

- 图片仍在内部保存原帖、图片直链、平台和作者信息；
- 只绑定当前人物下所选的白名单联系人；
- 强制用途为“只用于聊天”；
- 角色在私聊世界线里可以自然把它作为场景分享，不机械附加“网上找到的”；
- 不会进入朋友圈，也不会自动发给其他联系人。

目前需要你手工粘贴“原帖地址”和“图片文件直链”。审核通过后，隐藏决策器会看到当前联系人可用的少量图片摘要；当聊天场景确实适合发图时，它可以选择匹配项，核心再把图片作为独立动作加入微信 outbox。找不到合适图片时不会随便发一张，也不会影响文字回复。很多小红书页面不会直接显示图片直链，因此“从已登录浏览器自动提取候选”仍是下一阶段功能；手工导入链路已经可以自动选取和发送。
