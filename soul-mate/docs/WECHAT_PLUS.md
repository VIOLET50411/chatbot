# 微信 Plus 双账号接线与验收

## 固定绑定

| 人物 | 窗口顶部昵称 | 微信号 | Owner 在机器人微信里的备注 | 内部账号 ID |
| --- | --- | --- | --- | --- |
| 杜佳颖 | Sakino | Sakino411 | VIOLET | du-jiaying |
| 纪雨 | Locin | Theonlywan1 | VIOLET | ji-yu |

窗口顶部昵称用于 Plus 找窗口，微信号用于人工核对身份，`VIOLET` 用于找到白名单会话，内部账号 ID 用于隔离数据库和队列。四者不能互相替代。

一份 Plus 可以顺序控制同一台已授权 Windows 电脑上的多个微信窗口。两个代理实例分别维护心跳和入站缓冲，但所有微信 UI 操作共用一把进程锁，因此不会并行点击两个窗口。只有账号分布在两台电脑时，第二台才需要自己的授权。

## 上线前检查

1. Docker Desktop 已启动，`docker compose ps` 中 `soul-mate-core` 为 healthy。
2. Windows 未锁屏、未休眠；两个微信主窗口都已登录并展开。
3. 在项目环境检查授权：

   ```powershell
   .\.venv-host\Scripts\wxautox4.exe auth check --json
   ```

4. 管理台“微信与媒体”切换两个人物，核对窗口昵称、微信号、VIOLET 和内部账号 ID。
5. 主动消息与朋友圈保持关闭。

## 只读窗口预检

```powershell
.\scripts\start_wxautox_bridge.ps1 -CheckOnly
```

该命令从核心读取带版本的批准绑定，然后仅实例化指定窗口并检查在线状态。它不会建立监听、读取会话正文或领取发送动作。两个结果都必须是 `window_ready: true`；任何一个失败都先处理窗口，不要直接启动代理。

首次可分别检查，避免另一个未登录账号阻塞 canary：

```powershell
.\scripts\start_wxautox_bridge.ps1 -CheckOnly -AccountId ji-yu
.\scripts\start_wxautox_bridge.ps1 -CheckOnly -AccountId du-jiaying
```

## 启动桥接

```powershell
.\scripts\start_wxautox_bridge.ps1
```

只启动一个账号做首轮测试时加 `-AccountId ji-yu` 或 `-AccountId du-jiaying`。同一账号不能同时由完整桥接和单账号桥接控制。

链路验收必须使用隔离模式：

```powershell
.\scripts\start_wxautox_bridge.ps1 -AccountId ji-yu -ValidationMode
```

`-ValidationMode` 仍会正常识图、转写、调用人物模型并把回复发回微信，但这轮输入与输出不会写入正式聊天史、长期记忆，不会修改关系数值，也不能成为人格演变证据。宿主入站账本和出站 ACK 仍会保留短 ID 与状态，便于检查重复发送。真正开始日常聊天时停止桥接，去掉 `-ValidationMode` 后重新启动。

验收模式的连续上下文只存在 Docker 当前进程内：按联系人最多保留 20 条、30 分钟，供“你是说今天吗”这类下一轮澄清正确理解上一问；它不进入正式会话表，Docker 重启后自动消失。多模态轮次还会在发送前检查是否只回答最后一句、追问对象是否含糊、是否弄反说话人。微信压缩的小尺寸截图会先放大并优先 OCR；如果视觉摘要与对方语音说明冲突，以对方说明为准。

启动后先只观察管理台心跳和联系人候选。核心绑定版本变化、窗口身份不一致、账号停用或昵称重复时，对应代理失败关闭，不得回退到另一个窗口。

Plus 回调会先把文字/附件摘要写入每账号独立的宿主 SQLite 缓冲，再异步上传 Docker。Docker 或网络短暂中断不会丢已经捕获的消息。出站通过租约领取；明确成功才 ACK，明确未发送才允许 NACK 重试，调用微信 UI 后无法确认结果时进入 `delivery_unknown`，禁止盲目重发。

## 人工测试顺序

由 Owner 分别从两个 VIOLET 会话发送，机器人不会替 Owner 发首条测试消息：

1. 普通文字各一条，确认人物和窗口完全对应。
2. 连续发送五条短消息，确认 8 秒静默窗口后只生成一次。
3. 发送明确的情绪表达，再说“只听我说”，确认不会立即说教或给建议。
4. 明确请求分析，确认先问少量关键信息再给可执行建议。
5. 连续发送“你看这个”＋一张图片＋一段短语音，确认三个信息无论图片/语音先后都只生成一次，而且回复同时理解图片与语音。
6. Plus 转写为空时安全跳过；识图失败时只能承认没看清，不能编造。
7. 重启 Docker、桥接和网络，确认入站恢复、ACK 幂等和零重复发送。

之后进行两小时 canary，再进行 24 小时双账号浸泡。通过标准是零串号、零重复、零未知联系人发送、媒体故障不影响文字。

## 修改绑定

日常换绑在管理台完成，不改 `.env`：选择人物，填写新窗口昵称和微信号，勾选“确认账号身份正确”，保存后核心生成新绑定版本。先停止旧代理，再运行 `-CheckOnly`，通过后重新启动。

修改 Owner 的微信备注或外部标识时，在“白名单联系人”执行换绑，保留原 `contact_id`，这样历史、记忆和关系进度不会重置。发生冲突时只能人工选择合并或取消。

## 常见故障

- 找不到窗口：展开主窗口、核对账号自身昵称、确认桌面未锁屏；`VIOLET` 不是窗口昵称。
- Plus 显示未激活：必须使用项目 `.venv-host` 中的官方命令激活，不把激活码写进项目。
- 心跳在线但不能发：检查白名单显示名、绑定版本、outbox 的 `delivery_unknown` 和窗口是否仍在线。
- 图片/表情失败：先关闭对应功能开关；文字链路应继续工作。
- 电脑关机：本地核心与微信均暂停；VPS 模式下核心继续，但 Windows 微信仍暂停。
