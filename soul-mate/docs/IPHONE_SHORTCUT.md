# iPhone 快捷指令：把手机状态发给 Soul Mate

这部分不是 PWA 聊天本身。它负责让杜佳颖和纪雨在回答时看到你明确授权的手机状态，例如电量、最近打开的 App、城市、步数、睡眠和心率摘要。

系统采用“iPhone 主动 POST 一次快照”的方式，不会从服务器反向控制手机，也不会持续读取屏幕。设备口令放在 JSON 请求体中，不放在 URL 里。

## 一、先准备可从 iPhone 打开的 HTTPS 地址

本机 Docker 地址 `http://127.0.0.1:8080` 只能给电脑自己访问。iPhone 建议使用 Tailscale 私网 HTTPS：

1. Windows 管理员 PowerShell 执行：

   ```powershell
   winget install --id Tailscale.Tailscale -e
   ```

2. iPhone 从 App Store 安装 Tailscale。
3. 两边登录同一个 Tailscale 账号，并保持连接。
4. 启动 Docker 后，在项目目录的管理员 PowerShell 执行：

   ```powershell
   .\scripts\configure_tailscale_serve.ps1
   ```

5. 记下脚本输出的 `https://电脑名.xxx.ts.net`。后文用它替换 `<你的私网地址>`。

Tailscale Serve 只在你的 tailnet 中提供服务，不是公开网址。电脑关机、休眠、Docker 或 Tailscale 停止时，快捷指令会暂时发送失败；已保存的数据不会丢。

## 二、在管理台生成设备口令

1. 打开管理台 `日志与设置`。
2. 找到“手机状态与健康数据”。
3. 设备名称填写 `iPhone 17`，保留天数建议先用 `7`。
4. 点“生成手机接入口令”。
5. 立即复制口令到密码管理器。页面关闭后不会回显原文。
6. 按你的接受程度勾选电量/App/城市/步数/睡眠/心率。未勾选的字段即使快捷指令上传，也会在服务器入口被丢弃。

请求地址固定为：

```text
<你的私网地址>/api/device/v1/push
```

例如：

```text
https://violet-pc.example-tailnet.ts.net/api/device/v1/push
```

如果你在 `127.0.0.1` 管理台创建了设备，页面显示的请求地址会带 `127.0.0.1`；在 iPhone 快捷指令中必须换成上面的 Tailscale HTTPS 地址。

## 三、先做最小版快捷指令

在 iPhone 打开“快捷指令”，新建一个名为 `Soul Mate 手机状态` 的快捷指令，按下面顺序添加动作：

1. `获取电池电量`，保留结果变量。
2. `获取电池状态` 或系统当前版本里对应的充电状态动作，得到是否正在充电。
3. `当前日期`。
4. `格式化日期`，格式选择 ISO 8601；如果界面没有 ISO 选项，可用自定义格式 `yyyy-MM-dd'T'HH:mm:ssZZZZZ`。
5. `获取设备详细信息`，选择设备名称。
6. 添加一个`词典`，键名必须使用下面的英文：

   ```json
   {
     "device_token": "管理台刚生成的设备口令",
     "timestamp": "格式化后的当前日期",
     "device": "设备名称",
     "battery": "电池电量变量",
     "charging": "充电状态变量"
   }
   ```

   在快捷指令里不要把变量手打成普通文字；点值的位置，选择前面动作产生的魔法变量。`charging` 必须是布尔值，不要写成字符串“是/否”。

7. 添加`获取 URL 内容`：
   - URL：`<你的私网地址>/api/device/v1/push`
   - 方法：`POST`
   - 请求体：`JSON`
   - JSON：选择上一步的词典
8. 最后添加`显示通知`，内容写 `Soul Mate 状态已发送`，只在首次调试时保留。
9. 手动运行一次。iOS 首次会询问网络和相关数据权限，选择允许。

回到管理台，“iPhone 17”下方应出现“最近收到……”，并能展开查看最近一次上传数据。

## 四、逐项增加可选数据

先确保最小版成功，再逐项加；这样某个 Health 权限或动作名称变化时，不会让整条指令一起失效。

### 最近打开的 App

最稳定的方式是为需要关心的 App 建独立自动化：

1. 复制 `Soul Mate 手机状态`，命名为 `Soul Mate 午夜 App`。
2. 在词典加入 `app_name`，值直接写这个自动化对应的 App 名，例如 `微信` 或 `小红书`。
3. 在“自动化”中选择“App”，选择“打开时”，勾选对应 App。
4. 选择“立即运行”。调试通过后可关闭运行通知。

如果一次选了多个 App，快捷指令通常无法可靠知道究竟是哪一个触发；因此推荐每个重点 App 复制一份，并写固定 `app_name`。

### 城市级位置

1. 添加`获取当前位置`。
2. 从位置获取“城市”，只把城市文字写入 `city`。
3. 不上传经纬度。`location_accuracy_m` 可不填。

位置会增加耗电和权限提示；不需要时在管理台关闭“所在城市”，并从快捷指令删除相关动作。

### 步数与活动能量

1. 使用“查找健康样本”，类型选择“步数”，时间范围为今天。
2. 使用“计算统计信息”或“计算总和”，得到今日步数。
3. 新建一个内层`词典`，加入 `steps`。
4. 把这个内层词典作为外层词典的 `health` 值。

可选加入 `active_energy_kcal`，值为今天“活动能量”的总和。

### 睡眠与心率

可在 `health` 词典继续加入：

```json
{
  "sleep_minutes": 420,
  "heart_rate_avg": 72,
  "heart_rate_max": 118
}
```

- `sleep_minutes` 是分钟数，不是小时文字。
- 心率只上传当天摘要，不上传逐条 Health 样本。
- Apple Health 的睡眠来源可能同时包含手机、手表和手工记录，第一次要在快捷指令的结果预览中确认没有重复求和。

最终完整请求示例：

```json
{
  "device_token": "只放在你自己的快捷指令中",
  "timestamp": "2026-08-10T09:30:00+08:00",
  "device": "iPhone 17",
  "battery": 63,
  "charging": false,
  "network": "Wi-Fi",
  "focus_mode": "勿扰模式",
  "app_name": "小红书",
  "city": "重庆",
  "health": {
    "steps": 5832,
    "active_energy_kcal": 336,
    "sleep_minutes": 421,
    "heart_rate_avg": 72,
    "heart_rate_max": 118
  }
}
```

## 五、推荐自动化

先启用低频触发，确认不会频繁弹权限或耗电：

- 每天 08:30、14:00、22:30 各一次；
- 接入充电器时一次；
- 打开微信、小红书等重点 App 时，可只在夜间版本里上报固定 `app_name`；
- 不建议每分钟运行，也不需要后台长连接。

杜佳颖和纪雨都能使用同一份已授权设备摘要，但它只是当轮环境信息，不会写成人格事实。机器人不能据此诊断健康、指责你或声称看见了未上传的信息。

## 六、故障排查

| 现象 | 处理 |
| --- | --- |
| `401` | 设备口令写错、已经轮换或设备已暂停；回管理台生成新口令并替换快捷指令 |
| `422` | JSON 字段类型不对，常见是把电量/步数写成文字，或所有已授权字段都为空 |
| 无法连接服务器 | 先在 iPhone Safari 打开 `<私网地址>/healthz`；确认 Tailscale、Docker 和电脑都在线 |
| 管理台仍显示“没收到数据” | 在快捷指令最后临时加“显示结果”，检查词典和网络响应 |
| Health 没有数据 | 在 iPhone“设置 → 隐私与安全性 → 健康 → 快捷指令”确认权限，并检查当天确实有样本 |
| 重复记录 | 相同设备、相同时间和相同内容会幂等去重；检查自动化是否在多个地方重复触发 |

Apple 官方说明可参考[快捷指令中的获取操作](https://support.apple.com/guide/shortcuts/apd5c2bd430f/ios)和[iPhone 自动化入口](https://support.apple.com/guide/iphone/shortcuts-iph47e1c9d7d/ios)。
