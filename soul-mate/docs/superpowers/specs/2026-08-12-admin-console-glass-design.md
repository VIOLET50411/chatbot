# Soul Mate 管理台 AC 混合玻璃界面设计

日期：2026-08-12  
状态：已获 Owner 设计确认，待文档复核后实施  
适用范围：Owner 管理台，不改机器人后端协议；同时补齐 iPhone 17 主屏幕使用的响应式外壳

## 1. 目标与不做什么

管理台需要同时满足两种场景：桌面端查看运行状态、审核素材和调整配置；iPhone 17 上快速查看人物、联系人和桥接状态。视觉方向采用 A+C 混合：A 的清透工作台负责信息层级，C 的温和陪伴空间负责低对比背景、人物感和沉浸氛围。

本轮不把聊天 PWA 的视觉直接复制到管理台，不新增后端数据模型，不把大量内容放到透明玻璃上，不使用自动播放的装饰视频或高对比壁纸。PWA 聊天仍使用独立 `/chat` 外壳；管理台使用独立的 `admin-app-shell` 样式和入口状态。

## 2. 页面和导航结构

### 桌面宽屏

- 左侧固定导航：品牌、当前人物切换、五个管理区域、运行环境状态和退出。
- 右侧滚动内容：页面标题、当前人物/运行状态、主要操作、辅助信息。
- 侧栏宽度使用 CSS token，内容区使用最大阅读宽度，长文本不铺满整屏。

### 平板和窄桌面

- 侧栏收窄为图标栏，点击菜单按钮展开完整导航。
- 展开时显示半透明遮罩；点击遮罩、按 Escape 或切换路由后关闭。
- 重要操作仍保留文字标签，不依赖悬停提示。

### iPhone 17 管理台

- 侧栏变成底部玻璃标签栏，固定显示：运行总览、人设、联系人、微信、设置。
- 次级页面和危险操作使用底部 Sheet；Sheet 支持下滑关闭、取消按钮和 Escape 等价键盘行为。
- 人物切换固定在顶部状态区，始终显示头像、昵称和当前运行版本。
- 复杂表单按“常用设置 / 高级设置”折叠；保存按钮在键盘出现时仍保持可见。

## 3. 视觉系统

### 背景

- 浅色：低对比冷灰渐变，叠加很轻的柔和光斑和噪声纹理。
- 深色：深灰蓝背景，降低饱和度和高光强度，不使用纯黑大面积发光。
- 人物只提供轻微强调色，不改变整套管理台的结构和语义色。

### 玻璃层级

使用三个语义层级，避免“到处都是玻璃”：

1. 导航层：较强模糊、较高透明度、内侧高光和边缘阴影。
2. 浮层：人物切换、状态 Sheet、确认弹窗，使用更强的遮罩和前景对比。
3. 卡片层：轻玻璃，仅用于概览卡片和运行状态；正文卡片仍保持清晰底色。

玻璃实现使用 CSS 变量统一控制：背景透明度、模糊半径、饱和度、边框、内高光和阴影。浏览器不支持 `backdrop-filter` 时自动回退到不透明表面。审核正文、日志、表格、密集表单不使用透明背景。

### 颜色与文字

- 所有颜色通过现有 tokens 管理，组件中不新增散落的 hex 值。
- 正文维持至少 4.5:1 对比度，辅助文字至少 3:1；状态不能只靠颜色表达，同时显示文字。
- 页面标题、状态说明、卡片标题和辅助说明保持明确层级；移动端正文不小于 16px。
- 不使用 emoji 作为结构性图标，继续使用现有 SVG/文本图标体系。

## 4. 动效和交互

- 页面切换：180–260ms，使用 opacity 和 translate，不动画 width/height。
- 人物切换：头像、强调色、状态卡片采用共享元素过渡，保持空间连续感。
- 卡片首屏：最多做一次轻微错峰出现；长列表不逐条播放动画。
- 侧栏和 Sheet：打开使用弹性缓动，关闭更快；遮罩同时淡入淡出。
- 按钮：按下显示轻微缩放/高光，不能改变布局尺寸；异步按钮立即进入 loading 状态。
- `prefers-reduced-motion: reduce` 时关闭错峰、视差和弹性，只保留必要的状态变化。
- 所有点击、保存、失败和重试都有明确反馈；不允许“点了没有反应”。

## 5. iPhone 17 高度链和白条防护

管理台的 `/admin` 或根壳使用独立 `admin-app-shell` 标记：

- `html、body、#root、admin-app-shell` 的外层高度统一 `100vh`，不混用 `100%`、`100dvh` 和 fixed body。
- `viewport-fit=cover` 保留；safe-area 只用于顶部状态区、底部标签栏和 Sheet 内边距。
- 最外层背景覆盖 Home Indicator 区域，底部标签栏使用 `padding-bottom: env(safe-area-inset-bottom)`。
- VisualViewport 只用于键盘时滚动当前输入和调整 Sheet 内容，不重写外层高度。
- 管理台的 manifest/theme-color 状态和 `/chat` 分开处理，退出管理台时恢复原页面元数据。

## 6. 页面改造顺序

1. Shell、顶部人物切换和响应式导航。
2. 运行总览：状态卡、人物卡、队列和错误摘要。
3. 联系人：关系、记忆、检查点、开放话题和移动端 Sheet。
4. 设置：全局 Prompt、人物 API、外界信息、设备和部署配置。
5. 人设与素材：审核卡片、版本差异、敏感内容确认和回滚。
6. 微信与媒体：桥接状态、附件、图片/表情审核和朋友圈状态机。

每一步都复用统一的玻璃卡片、状态徽章、Sheet、确认框和错误反馈组件，避免每个页面单独实现一套风格。

## 7. 可访问性和性能验收

- 键盘 Tab 顺序与视觉顺序一致，所有图标按钮有 aria-label，焦点环始终可见。
- 可点击区域至少 44×44px；不依赖 hover；Sheet 和侧栏有明确关闭路径。
- 375×812、393×852、430×932、平板横屏和桌面宽屏无横向滚动。
- 浅色、深色和 reduced-motion 三种模式都检查文字、边框和状态对比度。
- 只对 transform/opacity 做动效；长列表不触发大量布局重排；异步内容预留空间避免跳动。
- 真机添加到主屏幕后确认底部无白边、键盘不遮挡输入、Home Indicator 背景连续。

## 8. 失败降级

- `backdrop-filter` 不可用：回退为高不透明度卡片，不影响信息阅读。
- VisualViewport 不可用：保持 `100vh` 外壳，使用普通滚动，不修改页面高度。
- 动效被系统关闭：页面仍保持状态、焦点和反馈完整。
- 管理台 API 失败：错误显示在对应卡片或表单附近，不清空用户已填写内容。

## 9. 实施约束

- 先补测试和可访问性检查，再改 CSS/组件。
- 每次本地修改后执行前端类型检查、生产构建和 `docker compose up -d --build`，复验 `/healthz`。
- 不改数据库、人物快照、微信绑定和后端行为。
- 不初始化或推送 Git；此设计文件由现有工作区备份机制保护。
